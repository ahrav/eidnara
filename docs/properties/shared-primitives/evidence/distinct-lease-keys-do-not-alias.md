# `distinct-lease-keys-do-not-alias`

- **Discovery:** architecture, security, and protocol-format passes.
- **Primary evidence:** public `LeaseKey` fields and constructor feed `LeaseKey::identity`, which asserts that no field contains the `U+001F` separator before joining them (`crates/lease/src/lib.rs:179-194`); `FileLeaseStore::lease_path` hashes that identity with public `fnv1a_hex`. PostgreSQL uses the same `fnv1a(key.identity())` value, computed in `advisory_key`, for its advisory lock and epoch row (`commons@89abb40 crates/cortexkit-store-postgres/src/lib.rs:67-72,355-389`).
- **Confirmed witness:** `("a\u{1f}b","c","d")` and `("a","b","c\u{1f}d")` would join to the same identity bytes; `LeaseKey::identity` panics on either key and names the offending field, so neither reaches a lease path. Fields stay public and are validated only at that call.
- **Additional mechanism:** FNV-1a-64 has no collision detection and the file stores no full identity. Practical targeted-collision cost was not established.
- **Existing evidence:** file-backend separation tests use separator-free values. `separator_in_a_key_field_fails_closed_instead_of_aliasing` (`crates/lease/src/lib.rs:1368-1388`) places the separator in each of the three fields and asserts the panic message names that field and `U+001F`. `identity_hash_derivation_is_stable` and `lease_path_vectors_are_version_stable` provide golden assertions, and PostgreSQL's archived `advisory_key_derivation_is_stable` did the same for the advisory key; none covers hash collisions.
- **Failure scenario:** distinct stores share the file lock path or PostgreSQL advisory lock and epoch row, causing false `Held`, a shared epoch counter, or false fencing.
- **Instrumentation:** identity and hash outputs are already publicly observable and covered by golden tests. Missing evidence is a stored full-key binding or collision check at the file path and PostgreSQL epoch row.
- **Open-question log:** `StorageDescriptor` fields are deserialized strings (`crates/storage-types/src/lib.rs:49-91`), but deployed value constraints are outside this repository. Descriptor-derived backend labels are closed to the `Sqlite` and `Postgres` enum variants (`crates/storage-types/src/lib.rs:93-107`), although callers can still construct a public `LeaseKey` with an arbitrary backend string.
