# `store-schema-identity-matches-the-baseline`

- **Discovery:** storage schema-identity pass at U2, prompted by the one-baseline rule for every Eidnara-owned SQL family.
- **Primary evidence:** `ExpectedIdentity::for_baseline` (`crates/storage/src/lib.rs:841-907`) applies `crates/storage/baseline.sql` plus the consumer text to an in-memory database and records the resulting `sqlite_schema` inventory and the text's SHA-256; `classify` (`crates/storage/src/lib.rs:931-981`) reads `application_id`, `user_version`, the inventory, and the `format_marker` row and returns `Pristine`, `Baseline`, or `StoreError::Baseline` without writing; `apply` (`crates/storage/src/lib.rs:983-1015`) runs once for a pristine file inside the open transaction; `open_sqlite` (`crates/storage/src/lib.rs:617-727`) classifies before `pin_fence_durability` and before the fence transaction.
- **Existing evidence:** `fresh_file_matches_the_baseline_inventory` (`crates/storage/src/lib.rs:1754-1818`) reopens a fresh file raw and compares `application_id`, `user_version`, the single marker row, and every `sqlite_schema` row to `fixtures/schema/storage-inventory-v1.json`; `a_file_with_foreign_objects_is_refused_without_mutation` (`crates/storage/src/lib.rs:1879-1905`) compares the file bytes before and after the refusal and asserts no `-wal` or `-shm` appears; `a_consumer_baseline_is_applied_once_and_verified_on_reopen` (`crates/storage/src/lib.rs:1820-1860`) reopens under the same text, then under a different text; `a_baseline_that_does_not_apply_is_rejected_before_the_file_is_touched` (`crates/storage/src/lib.rs:1862-1877`) shows the text is validated before the file exists; `negative_database_fence_fails_closed` (`crates/storage/src/lib.rs:2544-2572`) drives the fence row negative through `ignore_check_constraints` and asserts `FenceCorrupt` with the row unchanged.
- **Existing evidence (schema stays fixed):** `fenced_callbacks_cannot_change_the_schema_so_the_store_stays_reopenable` (`crates/storage/src/lib.rs:1424-1454`) shows every main-schema DDL form is denied inside a fenced callback while a temporary table is allowed, and that the store reopens under its baseline afterward; `a_baseline_that_hooks_an_infrastructure_table_is_rejected` (`crates/storage/src/lib.rs:1395-1422`) shows a consumer baseline cannot attach a trigger or index to `fence` or `format_marker`, so no baseline can undo the marker write or the fence claim underneath their read-back; `a_baseline_that_creates_temporary_objects_is_rejected` (`crates/storage/src/lib.rs:1184-1204`) shows a baseline whose objects would exist on the first connection only is refused, since the identity comparison covers `main.sqlite_schema` alone; `a_baseline_that_attaches_or_redefines_infrastructure_is_rejected` (`crates/storage/src/lib.rs:1227-1268`) shows the same for a baseline that attaches a database, where the `deny_baseline_escapes` authorizer denies `ATTACH`, `DETACH`, pragma writes, and transaction control before the statement runs, so a detached attachment cannot hide and a `writable_schema` or `ignore_check_constraints` setting cannot outlive the baseline onto the callback connection (`a_baseline_that_attaches_a_file_never_writes_to_it` (`crates/storage/src/lib.rs:1270-1289`) asserts the external path is never created), and shows that the `fence` and `format_marker` definitions from `baseline.sql` must survive the consumer text unchanged, so a redefined fence cannot pass the first open and refuse the second.
- **Failure scenario:** a foreign or half-formed file is treated as this store and written to, a foreign file with committed WAL frames is recovered or checkpointed by the read-write open that was meant to refuse it, a foreign `fence` row raises the lease floor before the file is classified, or a renamed table makes the floor read zero for a database that already recorded a higher epoch. `inspect_existing` (`crates/storage/src/lib.rs:909-929`) classifies an existing file on a read-only connection and reads the floor only from a `Baseline` file (`a_refused_foreign_wal_database_is_left_unrecovered`, `a_foreign_fence_row_does_not_raise_the_lease_floor`).
- **Timing window:** none; classification is a read on the same connection that later claims the fence.
- **Instrumentation:** `sqlite_schema`, `PRAGMA application_id`, `PRAGMA user_version`, and the `format_marker` row are the oracles; the fixture is generated by `cargo run -p storage --example schema-inventory` and pinned by its receipt hash.
- **Audit verdict (U2): pass. The fixture values are literals in a checked-in file, not derived from the constants under test at assertion time; a mutant that renames either table, drops a `CHECK`, or changes the application id fails the fixture comparison, and a mutant that writes before classifying fails the byte comparison.
- **Open-question log:** none.
