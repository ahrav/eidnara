## Evidence trail

A verdict of a transient reason (`deadline`, `object_unreadable`, `repository_unopenable`, `repository_unbound`), a deadline at classification or at the commit, a Kernel refusal of the classification or the commit, and a `changed` decision each call `transient` (`crates/daemon/src/attestation_verifier/bounded_pass.rs:610`), and a degraded witness calls `retry` (`:595`) directly; `transient` calls `retry` under `unavailable_skipped`. `retry` counts one attempt per pass for the decision, shared across all of these outcomes; the K-th (`MAX_ATTEMPTS`, `:84`, 3) resolves it under `witness_degraded_skipped` when its witness degraded and `unavailable_skipped` otherwise, so the cursor passes it. A classification read that finds a new store incarnation spends no attempt and stops the project, because the next pass resets the project's state. A refusal of the commit-target read, the decision page read, the page's batched standing read for a store-wide reason, or the attestation-state read stops the project or the pass without spending an attempt; a batched standing refusal one row can cause (an invalid id, a corrupt row, a malformed field) leaves each decision to its own classification read, which spends an attempt, and `invalid_write_set` resolves the decision at once. A root whose repository is unreadable, or whose walk spends its own share of the pass, binds no repository for the pass and is derived again next pass, so its decisions classify `repository_unbound` and take the same K-bounded path; a root whose identity is the project digest alone is derived again on the pass after one of the project's decisions classifies `repository_unbound` (`crates/daemon/src/attestation_verifier/bounded_pass.rs:424`), so a repository that gains its first commit binds its `git:` identity before the decision's K attempts run out; a derivation the pass deadline cuts short passes over the project before any decision is read and spends no attempt. `roots` (`crates/daemon/src/attestation_verifier/bounded_pass.rs:395`) tells the two `Budget` failures apart by the guard `clock.budget().is_exhausted()` (`:412`): an exhausted pass budget returns from `roots`, and a walk-share `Budget` takes the same arm as `Unreadable`, so its decisions count `unavailable_repository_unbound`. A pass continues past an unresolved decision to the ones behind it within its budgets, and the task passes again after `RETRY_INTERVAL` (5 s) when a pass progressed or failed.

## Failure scenario

A head decision consuming every pass.

## Timing windows and dependencies

Passes at the retry interval while the head's reason persists.

## What a test must construct
