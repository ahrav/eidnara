# `store-schema-identity-matches-the-baseline`

- **Discovery:** storage schema-identity pass at U2, prompted by the one-baseline rule for every Eidnara-owned SQL family.
- **Primary evidence:** `ExpectedIdentity::for_baseline` (`crates/storage/src/lib.rs:1076-1142`) applies `crates/storage/baseline.sql` plus the consumer text to an in-memory database and records the resulting `sqlite_schema` inventory and the text's SHA-256; `classify` (`crates/storage/src/lib.rs:1203-1253`) reads `application_id`, `user_version`, the inventory, and the `format_marker` row and returns `Pristine`, `Baseline`, or `StoreError::Baseline` without writing; `apply` (`crates/storage/src/lib.rs:1255-1287`) runs once for a pristine file inside the open transaction; `open_sqlite` (`crates/storage/src/lib.rs:682-831`) classifies before `pin_fence_durability` and before the fence transaction.
- **Existing evidence:** `fresh_file_matches_the_baseline_inventory` (`crates/storage/src/lib.rs:2505-2569`) reopens a fresh file raw and compares `application_id`, `user_version`, the single marker row, and every `sqlite_schema` row to `fixtures/schema/storage-inventory-v1.json`; `a_file_with_foreign_objects_is_refused_without_mutation` (`crates/storage/src/lib.rs:2630-2656`) compares the file bytes before and after the refusal and asserts no `-wal` or `-shm` appears; `a_consumer_baseline_is_applied_once_and_verified_on_reopen` (`crates/storage/src/lib.rs:2571-2611`) reopens under the same text, then under a different text; `a_baseline_that_does_not_apply_is_rejected_before_the_file_is_touched` (`crates/storage/src/lib.rs:2613-2628`) shows the text is validated before the file exists; `negative_database_fence_fails_closed` (`crates/storage/src/lib.rs:3295-3323`) drives the fence row negative through `ignore_check_constraints` and asserts `FenceCorrupt` with the row unchanged.
- **Existing evidence (schema stays fixed):** `fenced_callbacks_cannot_change_the_schema_so_the_store_stays_reopenable` (`crates/storage/src/lib.rs:2174-2204`) shows every main-schema DDL form is denied inside a fenced callback while a temporary table is allowed, and that the store reopens under its baseline afterward; `a_baseline_that_hooks_an_infrastructure_table_is_rejected` (`crates/storage/src/lib.rs:2145-2172`) shows a consumer baseline cannot attach a trigger or index to `fence` or `format_marker`, so no baseline can undo the marker write or the fence claim underneath their read-back; `a_baseline_that_creates_temporary_objects_is_rejected` (`crates/storage/src/lib.rs:1484-1504`) shows a baseline whose objects would exist on the first connection only is refused: `for_baseline` counts `temp.sqlite_schema` on the scratch connection after applying the text and rejects a non-zero count, since a temporary object lives on the creating connection alone while the persisted inventory that `classify` compares is read from `main.sqlite_schema`; `a_baseline_that_attaches_or_redefines_infrastructure_is_rejected` (`crates/storage/src/lib.rs:1550-1609`) shows the same for a baseline that attaches a database, where the `deny_baseline_escapes` authorizer denies `ATTACH`, `DETACH`, pragma writes, and transaction control before the statement runs, so a detached attachment cannot hide and a `writable_schema` or `ignore_check_constraints` setting cannot outlive the baseline onto the callback connection (`a_baseline_that_attaches_a_file_never_writes_to_it` (`crates/storage/src/lib.rs:1611-1630`) asserts the external path is never created), and shows that the `fence` and `format_marker` definitions from `baseline.sql` must survive the consumer text unchanged, so a redefined fence cannot pass the first open and refuse the second.
- **Failure scenario:** a foreign or half-formed file is treated as this store and written to, a foreign file with committed WAL frames is recovered or checkpointed by the read-write open that was meant to refuse it, a foreign `fence` row raises the lease floor before the file is classified, or a renamed table makes the floor read zero for a database that already recorded a higher epoch. `inspect_existing` (`crates/storage/src/lib.rs:1144-1192`) classifies an existing file on a read-only connection, reads the floor only from a `Baseline` file, and pins the file's device and inode; the read-write open is refused before its first statement when the path has been re-pointed since (`file_identity_follows_the_inode_not_the_bytes` (`crates/storage/src/lib.rs:1806-1831`)). The inspection creates no sidecar on the inspected path: with no `-wal` it opens the file `immutable`; with a `-wal` or `-journal` it opens a private copy read-write so the WAL is replayed or the hot journal rolled back before classification (`a_store_with_a_hot_rollback_journal_is_classified_after_rollback`, `a_refused_foreign_wal_mode_database_gains_no_sidecars`, `a_store_left_with_wal_frames_reopens_above_the_wal_epoch`). A `Baseline` file without a `fence` row, and a fenced write that finds none, return `StoreError::FenceMissing` (`an_initialized_store_without_a_fence_row_is_refused`); `deny_baseline_escapes` also refuses baseline rows in `fence` or `format_marker`. Open question: the interval between SQLite's `open(2)` and the identity check is not closed; closing it needs SQLite to open by descriptor, which the C API does not offer without a custom VFS (`a_refused_foreign_wal_database_is_left_unrecovered`, `a_foreign_fence_row_does_not_raise_the_lease_floor`).
- **Timing window:** none; classification is a read on the same connection that later claims the fence.
- **Instrumentation:** `sqlite_schema`, `PRAGMA application_id`, `PRAGMA user_version`, and the `format_marker` row are the oracles; the fixture is generated by `cargo run -p storage --example schema-inventory` and pinned by its receipt hash.
- **Audit verdict (U2): pass. The fixture values are literals in a checked-in file, not derived from the constants under test at assertion time; a mutant that renames either table, drops a `CHECK`, or changes the application id fails the fixture comparison, and a mutant that writes before classifying fails the byte comparison.
- **Open-question log:** none.
