# `tokenizer-over-long-pieces-are-chunked-and-bounded`

- **Discovery:** U3, from the crate documentation in `crates/tokenizer/src/lib.rs`, which states that tiktoken's merge loop is quadratic in the byte length of one pre-token piece and that pieces above `MAX_PIECE_BYTES` are split before merging.
- **Primary evidence:** `MAX_PIECE_BYTES` is `4096`. `encode_bounded` returns the plain `CoreBPE::encode_ordinary` result when the whole text fits under the cap; otherwise it walks the pre-tokenizer matches, hands each span between over-long pieces to `CoreBPE` whole, and encodes each over-long piece as `char_chunks` of at most `MAX_PIECE_BYTES` bytes. `char_chunks` advances to the last `char` boundary at or before the cap, so a chunk never splits a multi-byte character. `estimate_tokens` is `encode_ordinary(text).len()` with an early return for empty input.
- **Existing evidence:** `over_long_piece_is_chunked_and_bounded` builds ` a...a` at three caps plus 17 bytes inside `prefix` and ` suffix`, and asserts the ids equal `encode_ordinary("prefix")` followed by `encode_ordinary` over each `MAX_PIECE_BYTES` slice of the piece and then `encode_ordinary(" suffix")`, and that `estimate_tokens` matches. `over_long_cjk_piece_keeps_char_boundaries` encodes a four-byte-character run above the cap; byte-based chunking would slice mid-codepoint and panic, and the test also asserts a plausible token count. `long_text_without_over_long_piece_is_unaffected_by_bound` repeats a sentence past the cap with no over-long piece and asserts the whole encoding equals the per-sentence concatenation. All three live in `crates/tokenizer/tests/token_golden.rs` and pass on Rust 1.98 and stable.
- **Failure scenario:** the cap is removed or raised so a long unpunctuated run takes seconds, or chunking moves to byte offsets and splits a character.
- **Timing window:** none; the bound is a per-call cost property.
- **Instrumentation:** none.
- **Audit verdict (U3):** pass. The record exists so that a campaign neither regresses the bound nor demands oracle equality for a chunked piece, which the crate deliberately does not promise; the oracle-equality record `tokenizer-encoding-matches-the-independent-oracle` covers pieces at or below the cap.
- **Open-question log:** none.
