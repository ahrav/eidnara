## Independent situation markers

All names are fixed literals. Each marker has an independent `sometimes`
assertion over its own finite input predicate. Each can fire on a correct
implementation and reports its own unfired result. There is no combined runtime
marker or aggregate predicate. No marker is set from a safety assertion result.

1. `typed_wire_identity_plugin_shapes` - `sometimes`: the supplied baseline corpus has all
   seven emitted block kinds; tool flags absent and true for calls/results;
   output text, error_text, content, and error_content; optional signature,
   filename, and opaque arc absent/present; media data/url/opaque sources;
   provider extras absent/present; escaped keys and non-ASCII payloads. The
   corpus is classified before decoding with the candidate implementation.
2. `typed_wire_identity_default_forms` - `sometimes`: inputs include explicit false and true
   metadata, plugin absent/true flags, typed false call and result, an old
   frozen synthetic pair, and separately labeled explicit-false and unknown
   envelope normalization controls. It does not require output to differ.
3. `typed_wire_identity_fresh_and_sidecar` - `sometimes`: a served construction is invoked
   without reusable projected receipts, and sidecar inputs include no codec
   namespace, two different stamps on equal noncodec content, and a separately
   changed noncodec namespace. Include normal plugin absent/true tool flags,
   typed false tools, and a separately classified old stamped-row input. It
   does not require mismatched hashes or prove old stamps are only ephemeral.
4. `typed_wire_identity_receipt_candidates` - `sometimes`: inputs include missing positions,
   a present unequal position, repeated equal candidates, typed-equal blocks
   from different construction paths, and floating signed zeros in both orders
   with integer zero distinct in the fixture. Independent receipt sentinels
   make candidate choice observable without requiring wrong reuse.
5. `typed_wire_identity_old_rows` - `sometimes`: a baseline-produced nonempty raw array and
   known ordinal bounds are loaded into the real recovery input alongside an
   independent expected ID list. A parser failure cannot suppress this marker.
6. `typed_wire_identity_synthetic_snapshot_inputs` - `sometimes`: the production chunk
   builder receives both eligible real blocks and flagged/effectively synthetic
   todo blocks within the tested range. It does not require synthetic output
   items. A deliberately fabricated item is labeled test-only.
7. `typed_wire_identity_cold_durable_state` - `sometimes`: old ingress identities, a frozen
   pair, and served receipts are nonempty before a new handler/cache set is
   constructed empty; equivalent warm inputs are also supplied. An empty new
   store or mere process spawn cannot satisfy the predicate.
8. `typed_wire_identity_shared_sibling_edit` - `sometimes`: at least two source aliases and
   two normalized blocks exist, then an owned clone receives a real single
   block edit while an untouched sibling carries retained typed payload.
   The predicate observes setup and the edit request, not sibling corruption.
9. `typed_wire_identity_typed_only_shapes` - `sometimes`: a separate typed
   fixture matrix contains all seven `BlockKind` variants: text, reasoning,
   redacted_reasoning, tool_call, tool_result, media, and opaque. It contains
   all seven `OutputKind` variants: text, json, error_text, error_json,
   execution_denied, content, and error_content. Denial includes explicit
   `reason:null` and a nonnull reason; empty reason is distinct. Reasoning
   signatures, media filenames, and opaque arcs cover absent/null and present
   forms, including empty strings where valid. Include false/true tool flags,
   empty/nonempty provider extras, all three result-block kinds, nested JSON,
   floating signed zeros, and integer zero. Classify these input cases before
   running candidate code. This marker is independent of the plugin's four
   emitted output variants and of every expected byte or policy result.
10. `typed_wire_identity_durable_hygiene` - `sometimes`: load a nonempty old
    evaluable baseline with an excluded block-byte-derived P part, then supply
    unchanged, append-only, and controlled-mutated inputs under fixed core,
    tags, protection, coverage, time, and bust mode with cold/warm memos. Observe
    the input baseline and cases, not loss of evaluability or changed hashes.
11. `typed_wire_identity_durable_anchor` - `sometimes`: load a completed
    descent's full anchor tuple and supply an unchanged valid P summary, a
    synthetic-head case, and separate missing/moved/mutated controls. Record
    stored state and intended inputs before validation; no rejection is needed
    to satisfy the marker.
12. `typed_wire_identity_byte_policy_inputs` - `sometimes`: supply a frozen P
    corpus whose baseline token/byte counts place cases below, at, and above
    the selected suffix, fold-trigger, byte-rounding, and emergency-rearm
    boundaries under a fixed estimator/context. Include tagged/untagged items,
    cold/warm caches, and separately labeled daemon-only consumers. Record
    preclassified inputs, not a changed fold, protection, or reduction result.

The reachability record rolls up the twelve independent assertion results.
If a marker stays false, first inspect its constructibility and collection
point. Do not weaken the safety check, add arbitrary sleeps, or declare a
finite campaign failure to be proof of failed formal liveness.

## Leverage ranking and ownership

1. Freeze and classify plugin/default fixtures. These expose the largest
   compatibility gap and support three properties without timing machinery.
2. Compare the three fresh byte bases and the equality-reuse matrix. These
   isolate ordering, double-encoding, namespace, and signed-zero failures.
3. Exercise per-block mutation with shared source snapshots. This separates
   alias noninterference from old unknown-field replay.
4. Supply old persisted arrays and cold-cache metadata. These cost more setup
   but are necessary for actual compatibility, hygiene, anchor, and diagnostic
   claims. Freeze numeric P outcomes instead of assuming hashes cover policy.
5. Add cross-binary in-flight restart only if the specification requires that
   stronger claim. A clean reopen is not crash evidence.
