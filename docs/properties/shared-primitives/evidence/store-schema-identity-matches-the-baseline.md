# `store-schema-identity-matches-the-baseline`

- **Discovery:** storage schema-identity pass at U2, prompted by the one-baseline rule for every Eidnara-owned SQL family.
- **Primary evidence:** `ExpectedIdentity::for_baseline` (`crates/storage/src/lib.rs:826-866`) applies `crates/storage/baseline.sql` plus the consumer text to an in-memory database and records the resulting `sqlite_schema` inventory and the text's SHA-256; `classify` (`crates/storage/src/lib.rs:868-918`) reads `application_id`, `user_version`, the inventory, and the `format_marker` row and returns `Pristine`, `Baseline`, or `StoreError::Baseline` without writing; `apply` (`crates/storage/src/lib.rs:920-952`) runs once for a pristine file inside the open transaction; `open_sqlite` (`crates/storage/src/lib.rs:589-694`) classifies before `pin_fence_durability` and before the fence transaction.
- **Existing evidence:** `fresh_file_matches_the_baseline_inventory` (`crates/storage/src/lib.rs:1502-1566`) reopens a fresh file raw and compares `application_id`, `user_version`, the single marker row, and every `sqlite_schema` row to `fixtures/schema/storage-inventory-v1.json`; `a_file_with_foreign_objects_is_refused_without_mutation` (`crates/storage/src/lib.rs:1627-1653`) compares the file bytes before and after the refusal and asserts no `-wal` or `-shm` appears; `a_consumer_baseline_is_applied_once_and_verified_on_reopen` (`crates/storage/src/lib.rs:1568-1608`) reopens under the same text, then under a different text; `a_baseline_that_does_not_apply_is_rejected_before_the_file_is_touched` (`crates/storage/src/lib.rs:1610-1625`) shows the text is validated before the file exists; `negative_database_fence_fails_closed` (`crates/storage/src/lib.rs:2292-2320`) drives the fence row negative through `ignore_check_constraints` and asserts `FenceCorrupt` with the row unchanged.
- **Existing evidence (schema stays fixed):** `fenced_callbacks_cannot_change_the_schema_so_the_store_stays_reopenable` (`crates/storage/src/lib.rs:1172-1202`) shows every main-schema DDL form is denied inside a fenced callback while a temporary table is allowed, and that the store reopens under its baseline afterward; `a_baseline_that_hooks_an_infrastructure_table_is_rejected` (`crates/storage/src/lib.rs:1143-1170`) shows a consumer baseline cannot attach a trigger or index to `fence` or `format_marker`, so no baseline can undo the marker write or the fence claim underneath their read-back; `a_baseline_that_creates_temporary_objects_is_rejected` (`crates/storage/src/lib.rs:1121-1141`) shows a baseline whose objects would exist on the first connection only is refused, since the identity comparison covers `main.sqlite_schema` alone.
- **Failure scenario:** a foreign or half-formed file is treated as this store and written to, or a renamed table makes `read_fence_epoch` return floor zero for a database that already recorded a higher epoch.
- **Timing window:** none; classification is a read on the same connection that later claims the fence.
- **Instrumentation:** `sqlite_schema`, `PRAGMA application_id`, `PRAGMA user_version`, and the `format_marker` row are the oracles; the fixture is generated by `cargo run -p storage --example schema-inventory` and pinned by its receipt hash.
- **Audit verdict (U2): pass. The fixture values are literals in a checked-in file, not derived from the constants under test at assertion time; a mutant that renames either table, drops a `CHECK`, or changes the application id fails the fixture comparison, and a mutant that writes before classifying fails the byte comparison.
- **Open-question log:** none.
